# 1. Context

## Problem

`gta3sc` can compile GTA3script into SCM bytecode, but it cannot yet go the
other way. A decompiler is needed to:

- **Enable integration (lit) tests.** The `BACKLOG.md` integration-tests item
  is explicitly *blocked on a decompiler* (or reuse of the legacy one). A
  machine-readable disassembly lets tests assert on generated bytecode.
- **Provide a library (and later CLI) decompile path.** The CLI `decompile`
  stub exists today (`docs/sdd/20260625-cli/subtasks/06-decompile-stub.md`);
  wiring it is a follow-up once this library/driver lands.
- **Reverse-engineer / inspect existing scripts** shipped with the games and by
  the modding community.

A decompiler already exists in the **legacy** codebase (`~/dev/gta3sc`,
`master` branch: `src/disassembler.{hpp,cpp}`, `src/decompiler_ir2.hpp`,
`src/main_decompile.cpp`). It is a **behavioural reference only** — its
architecture, memory model, and code shape are *not* to be copied. The rewrite
has clear design goals (simple, modular, efficient, conformant; see
`DESIGN.adoc`) that the legacy code does not meet.

## Goals

- Decode a compiled `MAIN.SCM` (GTA III / Vice City) into a faithful **IR2**
  textual disassembly (see [reference](reference-bytecode-format.md)).
- Follow the **same design philosophy as the compiler**: a driver orchestrating
  well-separated phases, a target-specific back end (`disasm/` ↔ `codegen/`),
  `DiagnosticHandler` for problems, and reuse of existing support types
  (`CommandTable` → `InverseCommandTable`, `FilePool`, arenas where they earn
  their keep).
- Introduce a **lazy decode IR** (`DisasmIR` via `CodeDecoder`): decode
  instructions on demand from a byte cursor, with **no intermediate decoded
  container** for the common print path. Analysis is optional except for
  classic IR2 label ids.
- Keep the architecture **open to high-level decompilation later** (uplifting
  `IF`/`WHILE`/`REPEAT`/`GOSUB` etc.) as additional, pluggable passes — without
  reworking the low-level core.

## Non-goals (this spec)

- **High-level / structured decompilation** (control-flow uplifting, variable
  naming, GTA3script output). Design must *accommodate* it; we do not build it.
- **GTA3script textual output** (`-emit-ir2` is the only mode; the legacy
  GTA3script path was itself disabled).
- **San Andreas** specifics: streamed scripts (`script.img`), IEEE-754 float
  encoding, array / text-label variable datatypes (`0x07`–`0x13`), and custom
  headers (CLEO and related). The design leaves seams for these; none are
  implemented now.
- **Recursive-traversal** disassembly. Linear sweep only for now; the strategy
  boundary is designed so recursive traversal drops in later.
- **Round-trip guarantee** (decompile→recompile→identical bytes) as a hard
  contract. It is a desirable test lever, not a spec requirement.

## Constraints

- **C++26**, repo conventions in `AGENTS.md` (naming, `///` docs, `class` vs
  `struct`, trailing return types, `clang-format`, doctest layout).
- Must not contradict `DESIGN.adoc`. This spec *extends* it with a decompiler
  section (see [04-plan](04-plan.md) for the doc update).
- IR nodes that *are* arena-allocated must remain trivially destructible and use
  `ArenaAllocator` (per existing IR invariants). The lazy `DisasmIR` path
  deliberately avoids arena allocation for the hot path (see design).
- Decode must be the **exact inverse** of `codegen::trilogy::CodeEmitter` /
  `CodeGen` for each supported version; the datatype-byte table in the
  [reference](reference-bytecode-format.md) is authoritative.

## Brownfield touchpoints (reused, not re-specified)

| Component | Role in decompiler |
|-----------|--------------------|
| `CommandTable` / `CommandDef` | Source of command defs; build `InverseCommandTable` from it |
| `InverseCommandTable` | Opcode → `CommandDef*` for decode/print (new; this spec) |
| `codegen::trilogy::CodeEmitter` | The encoder we invert; decode tables mirror it |
| `filesystem::FilePool` / `FileRange` | Register the `.scm`; byte offset → `FileLoc` for diagnostics |
| `DiagnosticHandler` / `DiagnosticDescriptor` | Unknown opcodes, corrupt headers, out-of-range branches |
| `driver::Compilation` | Structural template for `driver::Decompilation` |
| SDD process (`docs/sdd/`) | This spec |

CLI `run-decompile` stub exists but wiring it is a **follow-up**, not this spec.

## Glossary

- **SCM** — the compiled bytecode format for the 3D-era GTA games.
- **IR2** — the explicit, machine-oriented textual representation of SCM
  bytecode (datatype-suffixed literals, `@`/`%` labels, block directives). The
  decompiler's output format. Full grammar in the [reference](reference-bytecode-format.md#ir2-output-format).
- **Opcode / command id** — 16-bit little-endian value at the start of an
  instruction; high bit (`0x8000`) is the *not flag*, low 15 bits index a
  command.
- **Datatype byte** — the byte preceding most arguments, identifying its
  encoding (int8/16/32, float, variable, string, …). Some III/VC text labels
  have *no* datatype byte and are inferred from the command's parameters.
- **Segment / block** — a contiguous code region: the *main* segment, a
  *mission* segment, or (SA, later) a *streamed* script.
- **Linear sweep** — decode top-to-bottom, byte after byte. **Recursive
  traversal** — follow branch/label targets to distinguish code from data.
- **Lazy decode IR / `DisasmIR`** — a transient view of one decoded instruction
  (`ir/disasm-ir.hpp`), produced by `CodeDecoder` without building a container.
- **`CodeDecoder`** — semantics-free bytecode decoder; read counterpart of
  `CodeEmitter`.
- **`InverseCommandTable`** — `find_command` opcode → `CommandDef*` index
  derived from `CommandTable` (also `command_table()`).
- **`SegmentAnalyzer`** — analysis that builds label offsets + code/data map
  (`SegmentAnalysis`); not required to use `CodeDecoder` alone.
- **`SegmentWalker` / `DisasmEventSink`** — public linear walk emitting
  `on_label` / `on_command` / `on_undecoded_bytes` (see
  [05](05-disasm-walk-and-events.md)).
- **`MultifileDisasm` / `MultifileHeader`** — library entry for whole-SCM
  header split, analyze, walk, and IR2 (driver is a thin façade).
